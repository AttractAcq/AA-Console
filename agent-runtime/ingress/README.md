# Public ingress deployment contract

This service is the only trusted source of anonymous visitor IP metadata for the AA Console runtime. It is a reverse proxy for the existing `runtime.attractacq.com` API: it forwards admin and health requests unchanged except for unsafe forwarding/ingress headers, and signs the four anonymous `/public/*` route families before forwarding them. The core runtime verifies the HMAC, exact method/request target/raw body SHA-256, 30-second timestamp and a database-claimed one-use nonce before any public handler or quota write. Its quota key is the signed client IP. A missing nonce store or signing key denies the request.

## Required Railway topology

1. Create a **separate Railway project** with one production service: this ingress facade. Do not put a database, worker, gateway, log forwarder, private-network sandbox or any other service in that project/environment. Do not expose a TCP proxy. Railway's private network is scoped to a project/environment, so a sole-service project has no sibling that can directly reach this listener and forge `X-Real-IP`. A project/environment services inventory and networking screenshot are release evidence. [Railway private networking](https://docs.railway.com/networking/private-networking), [Railway domain scope](https://docs.railway.com/networking/domains/working-with-domains).
2. Deploy from repository root directory `/agent-runtime/ingress` using its Dockerfile. Set `PUBLIC_INGRESS_UPSTREAM_URL` to the **core runtime's separate HTTPS origin**, such as its Railway-generated domain. It must never point to `runtime.attractacq.com` after that name is moved to the facade, or it would loop. Set `PUBLIC_INGRESS_EXPECTED_PROJECT_ID` to this new project's ID and `PUBLIC_INGRESS_CORE_PROJECT_ID` to the existing runtime project's ID; startup compares both with Railway's injected `RAILWAY_PROJECT_ID` and refuses a same-project deployment or a configured TCP proxy. This check does not prove the project has no sibling services; verify the inventory separately. This facade has no Supabase/service-role, Anthropic, MCP, runtime shared, IP salt, or provider credentials.
3. Generate a **new** random 32-byte-or-longer hex/base64url `PUBLIC_INGRESS_HMAC_KEY`; place that same value on only the facade and core runtime. It must be different from the runtime status secret and public IP salt. The facade must have no readable copy of those existing secrets. The core needs migration 280's `claim_public_ingress_nonce_v1` before `PUBLIC_INGRESS_HMAC_REQUIRED=true`.
4. Keep existing public switches off. Deploy the core runtime with the new code, the proxy CIDR setting absent and `PUBLIC_INGRESS_HMAC_REQUIRED=false`. Deploy the facade under a temporary public Railway domain and verify it forwards `/health` and a signed public request to a staged core. Move `runtime.attractacq.com` to the facade, verify DNS/TLS and normal console calls, then set `PUBLIC_INGRESS_HMAC_REQUIRED=true` on the core. Test both the canonical facade and the direct core domain. Do not enable public routes until the direct core domain returns 403 for unsigned `/public/*` calls and the facade successfully signs them.
5. Capture release evidence: facade project/environment service inventory, no TCP proxy, facade and core deployed SHAs, masked presence/format of the distinct key, custom-domain target, normal and forged `X-Real-IP`/`X-Forwarded-For` probes through the public facade, direct-core rejection, tampered body/path/method rejection and nonce replay rejection across replicas. The exact client IP may be recorded in a restricted release packet, not general logs. Keep switches off if any proof fails.

Railway documents `X-Real-IP` as the client remote IP on its public HTTP edge and states that `X-Railway-Debug` only adds an upstream zone response header. [Railway public networking specifications](https://docs.railway.com/networking/public-networking/specs-and-limits), [Railway edge networking](https://docs.railway.com/networking/edge-networking). A [Railway employee](https://station.railway.com/questions/need-authoritative-client-ip-proxy-tru-090eac86) confirms the edge overwrites caller-supplied `X-Real-IP`, while private-network requests bypass sanitization. Railway does not publish stable or exclusive socket-peer CIDRs, and XFF hop count is not fixed. Do not configure `PUBLIC_TRUSTED_PROXY_CIDRS` or treat a one-time observed peer/XFF chain as proof.

## Local checks

Run `node --test server.test.mjs` in this directory. The tests use two temporary loopback HTTP servers and never contact production. The production Docker image contains only `server.mjs`; it needs Node 22, `PORT`, `PUBLIC_INGRESS_UPSTREAM_URL`, `PUBLIC_INGRESS_HMAC_KEY`, `PUBLIC_INGRESS_EXPECTED_PROJECT_ID` and `PUBLIC_INGRESS_CORE_PROJECT_ID`. The facade buffers at most 16 KiB per ordinary public request and 36 MiB for a proof submission, with a 120-second absolute body deadline. It rejects missing client identity, malformed target and oversized body before contacting the core. The core checks the envelope before buffering the body and then compares the digest with the exact bytes replayed to the existing handler.
