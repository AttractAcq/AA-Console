# SF34 — Build a brief from an approved idea

**Where.** Clients → [client] → Delivery → Content Production Factory → Briefs
**Owner.** Creative lead. **Reviewed.** 25 October 2026. **Part of** MF07, MF08, MF09.

## Do it
From an approved idea, queue the brief (or use **Approve & brief** in SF33). The brief agent
writes it from the idea, the campaign, the offer version and the intelligence.

A brief carries **Type**, **Format**, **Destination**, the body, and **Brief created at**.
**View brief** to read it.

## Set Format and Destination before anything is built
| `content_format` | Note |
|---|---|
| `single` | One image |
| `carousel` | Multiple frames, publishes whole (SF38) |
| `story` | Vertical (SF39) |
| `reel` | Stills, then motion (SF37) |

Getting these wrong wastes the build, and for the human route (SF44) it wastes a shoot.

## For a reel: the frame plan
The brief carries a structured frame plan — the beats. That structure is what lets you
regenerate one frame without redoing the others (SF35).

## States
`draft` → `approved` → `in_production` → `complete`, or `rejected`.
**Approve & build** approves the brief and queues the build.

## Gotcha
The brief is what QA later judges the asset against. A vague brief produces an unapprovable
asset and an argument about whether it is any good. Fix the brief, not the asset.
